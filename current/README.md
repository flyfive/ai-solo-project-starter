# 个人 AI 开发项目启动模板 V1.9.0

完整治理 + 分层上下文 + 按需读取。事实完整保存，日常任务只加载当前必需内容；不以删除历史、减少需求或省略测试换取上下文缩小。

## 使用

打开 `使用说明.html`，填写信息并复制初始化/接管提示词；备用入口 `CREATE_PROJECT.cmd`。需要 Python 3.11+ 和 Git。模板目录与业务项目目录分开。AI 负责内部维护命令，用户负责产品决策、必要授权和真实验收。

使用入口：[使用说明.html](使用说明.html)。页面预填路径仅为作者示例；请换成自己的实际 current 目录，目标项目必须独立。留空会回退该示例，并不代表路径已核验。

运行需 Python 3.11+ 与 Git；完整测试另需 Node.js 24，不需 pip/npm 包。工具自身个人自用优先；下列治理能力用于生成项目，不要求工具每次小改动打包或结案。采用 [MIT](LICENSE)，署名 FeiXiaorong；生成材料及业务代码边界见 [许可说明](LICENSE_STATUS.md)。

## Lite / Standard / Auto

| 能力 | Lite | Standard |
|---|---|---|
| 适用 | 一至三天、单执行器、自用小项目 | 长期、多模块、多阶段、正式交付 |
| 初始文件（含模板许可声明） | 23 | 36 |
| 永久需求 ID、完整修订、AC、Change、Git | 保留 | 保留 |
| Hot / 按 ID 读取 | 支持，索引在内存计算 | 支持，持久派生索引 |
| 独立决策正文、完整读取/执行协议 | 不新增 | 支持 |
| Parent Batch/Internal Units | 不启用 | 可选 |
| 发布基线、交付、结案 | 不启用 | 保留 |

Auto 继续按中英文描述和类型给出建议。客户/正式交付、账户/权限、敏感数据、支付、迁移、生产部署、多平台、硬件及不可逆风险直接触发 Standard；明确选择优先。没有第三种治理模式。

支持 generic、web-fullstack、desktop-windows、android、python-local-tool、hardware-pcb、ai-automation、data-platform。Lite→Standard 保留目录、Git、需求/历史和实现，继续要求所有者授权、模板校验、可回滚升级和基线审计；BLOCKED/PARTIAL 可按原有安全挂起流程恢复。不得降级。

## 三层上下文

- L1 Hot：START_HERE 项目简述、AGENTS 稳定规则、CURRENT_STATE、context.json 中的活动批次摘要与选定索引行。
- L2 Task：按 R/AC、Cxx、DEC 引用提取正式正文、相关阶段与代码，不加载整份需求/架构。
- L3 Cold：历史日志、关闭的 Batch/Change、旧修订/验收/包和完整原始测试输出。全部保存，默认不读；明确失败、冲突、兼容或追溯原因才按 ID/路径检索。

Standard 的 `.ai/context_index.json` 是派生导航，包含三种索引，不是事实副本，也不默认全文送入 AI。相关正文或执行规则变化后活动任务 stale，必须 PM 重读确认后刷新。Hook/health 校验过期索引和无效引用。

## 批次与证据

Standard 可把相关内部工作单元放入一个父批。Unit 局部测试、失败记录不可省略；父批结束统一回归和适用的消费者、浏览器、包、报告检查。普通项目仍可使用原批次。

L1 局部、L2 模块、L3 父批、L4 阶段、L5 发布；高风险至少 L4。使用精确 context_refs、父批或提升级别后启用分层测试契约，阶段/发布检查相应原始证据。旧请求保留原有严格测试契约，不冒充新分层保证。

`ai-evidence` 保存实际命令 stdout/stderr 或导入已有原始输出，生成 JSON summary。成功返回摘要，失败返回相关片段和证据地址；摘要不能代替原始证据。运行外部/付费/破坏性操作仍需已有授权。

## 完整性与边界

继续保留需求乐观锁、link 白名单、文档优先、人工验收、并行隔离、集成审核、发布范围、不可覆盖基线、交付哈希、冻结结案和事务回滚。V1.8.1 正式目录不修改。核心纯文件、Python 标准库和 Git，不依赖联网、AI 品牌、数据库或向量服务。

工具约束流程与文件一致性，不能证明操作者没有虚报角色/授权/测试。正常命令通过不等于自动满足全部产品 AC。磁盘校验可扫描完整索引与历史哈希；本版减少送入 AI 的内容，不宣称消除全部磁盘 I/O，也不估算 token。
