# 变更日志

## V1.9.2

- Standard 新增 `ai-handoff-batch`：真实 BLOCKED/PARTIAL 在具名继任与强绑定所有者授权下移交责任，保留非成功事实，不调用 PASS finalize。
- durable batch_handoff/1 历史与 runtime successor marker 分离；交接与继任启动均使用现有多文件回滚事务；open changes 拒绝，不迁移 Change。
- ai-start 重新验证冻结定义、身份与哈希，锁定具名继任；resume/context/memory 和 health 支持此状态。
- 产品版本升级；PROJECT/state schema_version 仍 1.9.0，旧输入及 Lite promotion 不变；不迁移真实项目。见 UPGRADE_V1.9.2.md。

- 增加真实初始化、运行、状态重读与兼容反例；结果见 TEST_INFRASTRUCTURE_DESIGN 的实施记录。
- 不自动迁移真实项目、不改写旧证据；人工三方合并见 UPGRADE_V1.9.1.md。

## V1.8.1

### 双模式升级闭环

- 新增 `ai-suspend-for-promotion` 内部入口；只有已如实记录为 `BLOCKED` 或 `PARTIAL` 的 Lite 批次才能在项目所有者授权后安全挂起；
- 挂起记录保留未完成内容、测试状态、未关闭变更、Git 和实现指纹，事务失败时恢复活动批次、状态和日志；
- Lite→Standard 升级现在同步更新 `START_HERE.md`、`AGENTS.md`、项目 `README.md`、context、handoff 和项目记忆；
- 升级后进入 Standard 基线待审计状态，补全架构、计划和记忆并通过完整审计前禁止启动批次或创建发布基线；
- 基线审计通过后自动恢复升级前挂起的批次。

### Auto、完整性和口径

- 客户或正式交付、账户与权限、敏感数据、支付、迁移、生产部署、多平台、硬件／PCB 和不可逆操作改为不可被短周期抵消的 Standard 硬触发条件；
- Lite 与 Standard 的并行、发布基线、最终验收及默认接管配置现在按模式生成；
- Standard 隐藏模板包增加整体和逐文件 SHA-256，初始化、健康检查和升级前都会验证；
- 健康检查增加入口文档模式标签、能力配置和升级基线状态一致性检查；
- 文档明确 Lite 是轻量需求和执行规划，不等同于 Standard 的完整规划与正式交付闭环；
- 回归套件扩展为 54 项。

## V1.8.0

### 双治理模式

- 新增 `Lite` 极简治理，面向一至三天、单执行器、自用且没有正式交付的小项目；
- 保留 `Standard` 标准治理，完整继承 V1.7.2 的需求、批次、发布、交付和结案能力；
- 项目技术类型与治理规模分离，同一 Profile 可以选择任一治理模式；
- 初始化器新增 `--governance-mode lite|standard|auto`；
- 未显式指定模式的非交互调用默认 Standard，保持旧调用兼容。

### 自动选择

- `auto` 根据中英文项目描述和技术类型计算可解释的治理建议；
- 正式交付、客户、多阶段、权限、支付、敏感数据、数据迁移、部署等信号提高 Standard 权重；
- 一至两天、极小脚本、个人小工具和快速验证等信号提高 Lite 权重；
- 手工 `lite` 或 `standard` 选择始终覆盖自动建议；
- 初始化输出最终模式和选择理由。

### Lite 原地升级 Standard

- Lite 从第一天使用与 Standard 相同的需求编号、修订历史、状态和 Git；
- 初始化时生成隐藏的、已渲染 Standard 文档扩展包，但 Lite 不加载这些文档；
- 新增 `ai-promote-standard` 内部命令；
- 升级必须由项目所有者授权，并要求没有活动批次和未关闭变更；
- 升级事务一次生成 Standard 文档并更新 TOML、项目状态和日志；
- 故障注入确认失败时所有已创建或修改文件完整回滚；
- 只允许 `lite → standard`，不允许降级；
- 并行执行、复杂架构变更、正式发布、客户交付、最终验收和结案在 Lite 中明确阻断并提示升级。

### 文档与验证

- `AGENTS.md`、`START_HERE.md`、项目 `README.md` 和 `CURRENT_STATE.md` 改为模式感知；
- 离线 `使用说明.html` 增加模式选择和双模式提示词；
- 回归套件扩展为 49 项，新增 Lite、Standard、Auto、Lite 需求修订、中文和英文判断、模式边界、所有者授权及升级事务测试；
- 八种技术 Profile 将分别验证 Lite 与 Standard，共 16 种初始化组合。

## V1.7.2

### 需求历史真实性

- 每个需求修订快照现在深拷贝并保存完整历史语义，包括验收描述与方法、用户说明及核对状态、帮助说明、已知限制和备注；
- 自动生成的 `REQUIREMENT_CHANGELOG.md` 展开完整历史内容，可直接还原任一旧版本；
- 登记表校验会拒绝缺少完整语义字段的修订快照，并拒绝当前语义与最新快照不一致；
- 需求登记表和四份派生文档改为跨文件事务，故障时全部恢复。

### 发布范围防遗漏

- 非空 `release_target` 在创建、修订和健康检查时必须通过 SemVer 校验；
- 非法目标在任何正式文件写入前整体拒绝；
- 发布基线显式记录本次纳入、无目标、未来版本、过期目标、历史已结案需求和无法精确匹配的目标；
- 无历史结案基线保护的过期目标或无法精确匹配的目标阻止发布，不再因字符串不匹配而静默退出范围；
- 已由 closed 基线冻结的旧版本需求记为历史，不会阻断所有者授权后的更高版本发布。
- 只有实际被 closed 基线需求清单冻结的需求版本才能归类为历史；
- 新建和修订需求不能再指向已结案版本，SemVer 核心数字严格限定为 ASCII。

### 跨平台与工程修复

- 新增 `build_package.py`，ZIP 条目统一使用 `/`，并执行 CRC、逐文件哈希和安全路径校验；
- 包内容使用确定性时间和权限元数据，同时生成 SHA-256 文件；ZIP 与 SHA 文件成对事务发布；
- 打包拒绝源码根外链接，排除常见工具缓存，并限制版本目录组件长度；
- `CREATE_PROJECT.cmd` 保留初始化器真实退出码；
- Git Hook 版本文字同步为 V1.7.2；
- 客户交付文档默认拒绝部分重生成；显式强制时整体事务刷新并校验 checklist/manifest；
- 最终验收改为基线、报告、状态和日志事务；
- 将并行集成综合测试拆成独立测试方法，降低慢速 CI 的单用例超时风险；
- 回归套件扩展为 42 项隔离测试，4 个工作线程下全部通过。

## V1.7.1

### 阻断缺陷

- 并行集成审核的每项必需测试现在必须为 `pass`；`fail`、`blocked`、`not_run`、未知和缺失状态都会保留活动批次及未关闭变更；
- `link` 改为严格追踪证据白名单，产品语义字段必须关联真实未关闭变更并通过 `revise` 修订；
- 已结案发布版本永久冻结，显式重开必须声明原结案版本和更高的新开发版本，且不能重建或替代旧版本基线。

### 工程完整性

- 发布基线创建与替代改为跨文件原子事务，故障时恢复所有目标文件；
- 正式交付物仅接受项目根目录内相对路径，并拒绝绝对路径、`..` 和链接逃逸；
- Windows 测试入口只探测解释器一次、测试只执行一次、无交互并原样返回退出码；
- 测试默认禁止 Python 字节码写入，临时 Git 项目自动清理并支持显式调试保留；
- Git 成为正式初始化的强制依赖，初始化必须成功完成初始提交；
- 同步 V1.7.1 版本、规则、验证与包内容文档。

### 回归验证

- 保留 V1.7 原有 10 项回归测试并新增 9 项综合回归测试；
- 新增用例覆盖本版要求的 22 类状态、权限、事务、路径、Windows 入口和清理场景；
- 远端 CI 配置保留，但本地验证不宣称远端矩阵已经执行。

## V1.7.0

### 批次状态机

- `PASS` 要求全部真实测试为 `pass` 且无阻塞；
- `PARTIAL/BLOCKED` 不再关闭批次或关联变更；
- 关联变更只有在实现完成并满足重新验收要求后才能关闭。

### 发布与交付

- 发布基线改为不可覆盖的独立编号；
- 同版本替代需要显式引用旧基线；
- 增加发布文件名碰撞保护；
- 基线记录原始 Git 提交并锁定已提交实现树；
- 客户交付物增加文件/目录 SHA-256、大小和文件数量验证；
- 客户可见及纳入发布范围的 active 需求必须具备完整证据。

### 需求并发与验收

- 需求修订和证据链接增加 `expected_current_version` 乐观锁；
- 需求语义修订必须关联真实未关闭变更；
- 单项验收条件 `waived` 必须填写批准理由。

### 项目生命周期

- 项目结案成为默认终态；
- 增加项目所有者授权的显式重开流程；
- 结案过程改为可回滚事务，避免半完成状态。

### 初始化与环境

- 项目名称、简介、路径采用安全 TOML 序列化；
- 初始化改为临时目录验证后原子发布；
- `--force` 会先备份旧目录；
- Git Hook 记录并优先使用实际可运行的 Python；
- 修复 Windows Microsoft Store 占位 `python` 导致 Hook 失败；
- 修复双击入口未使用脚本自身目录的问题。

### 文档与测试

- 修复 `AGENTS.md` 中项目记忆和当前状态的路径；
- 移除 `PITFALLS.md` 中不存在的命令；
- 新增可重复执行的自动化回归测试；
- 新增可选跨平台 CI 工作流；
