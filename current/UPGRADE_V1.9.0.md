# V1.9.0 升级说明与 V1.8.1 对照

## 定位

完整治理保持不变，优化每个任务的最小必要上下文。版本沿用现有 major.minor.patch，新增兼容能力使用1.9.0。V1.8.1原目录/包保留，新版单独目录和ZIP/SHA发布。

| V1.8.1 | V1.9.0 |
|---|---|
| 入口可能要求全文需求/Decision | 默认 Hot 后按明确 R/C/DEC 提取 |
| 读取计划主要是文件名 | manifest含选择器、引用、freshness、Cold边界 |
| registry含当前与全部修订 | 结构保留；日常提取只返回当前完整正文+AC |
| 架构普通章节 | 新模板稳定Cxx，可添加职责/依赖/代码/决定元数据 |
| Decision全文追加 | 兼容旧内联，Standard新Decision独立正文+导航 |
| 最近批次快照和手工重复状态 | 当前版本/阶段/唯一批次/阻断/引用/下一步自动快照 |
| PROJECT_MEMORY语义变化必写 | 只在摘要引用受影响时更新，不重复复制正文 |
| 批次关闭后运行JSON清理 | 同时保留结构化批次/Change/Unit历史 |
| 每个工作单元完整批次 | 可选Parent Batch内部Unit，父批统一关闭 |
| 测试列表 | 分层证据契约与原始输出/summary双通道 |
| 文档/需求一致性Hook | 加入索引、引用和规则失效检查 |
| Lite21文件/Standard31文件 | Lite22/Standard35，Lite不加持久索引与Standard协议 |

## 不变能力

8类项目、Lite/Standard/Auto建议、原子初始化、Git Hook、永久需求编号及修订语义、真实Change、AC、人工验收、并行集成审核、发布范围、不可覆盖基线、交付哈希、结案冻结、授权重开、单向治理升级、模板哈希与事务回滚均保留。

## 工程变更

新增标准库辅助脚本context_engine.py，主体维护引擎沿原结构接入。Hook读取解释器路径改用shell内建read，减少sed依赖；状态写回使用字面量替换，保留Windows反斜杠。没有重写旧状态机，没有新增外部基础设施。

## 兼容声明

旧命令与无扩展字段的批次JSON继续可用，仍执行原测试/验收门禁。新引用/父批/风险等级启用分层测试契约后，不得通过旧结果绕过所需原始证据。V1.8.1登记表不能直接把schema字符串改掉就声称完成迁移。已有真实项目没有被自动修改。
