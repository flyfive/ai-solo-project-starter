# 个人 AI 开发辅助工具

帮助具备本地文件、终端和 Git 权限的 AI 执行工具建立可接管的项目：保留需求与修订、批次状态、测试证据和必要验收，按需读取上下文。它不是自动证明需求正确的系统，也不是安全沙箱。

个人自用优先，准备公开分享，按实际需要修复和优化；不作为商业服务，不承诺固定更新周期、响应时间或全面兼容，不绑定特定 AI 品牌。“少敲命令”仍需要执行工具拥有相应本地权限。

## 前提

- 初始化/运行：Python **3.11+**（标准库，无 pip 依赖）和 Git。Windows 使用完整 Git for Windows，以运行生成项目的 shell Hook。
- 完整测试：另需 **Node.js 24** 执行页面脚本模拟测试，无 npm 依赖。先确认 `python --version`、`git --version`、`node --version`；Windows 的 `python` 不可用时可用已安装的 `py -3`。
- 初始化器在未找到 Git 身份时，仅在新项目仓库设置明确的占位身份，不修改全局配置。它不是作者署名；实际提交/公开前应自行核对项目身份。

## 从哪里开始

克隆或解压到自己的目录，进入 `current/`，打开 [使用说明.html](current/使用说明.html)。页面模板路径预填的是**作者示例**，不是自动识别的路径；换成你实际解压位置下的 current，目标项目填写另一个独立目录。清空模板路径仍会回退作者示例，因此执行前必须核对；手动填写的路径会保留。

- **Lite**：小型、单执行器项目，保留需求、测试与适用人工验收，不套用正式交付/结案门禁。
- **Standard**：复杂或需要完整阶段/交付治理的项目；原授权、文档优先、测试和人工验收门禁保持。
- **Auto**：初始化时建议 Lite/Standard，不是第三模式；接管时必须读取新项目 PROJECT.toml 的实际模式，不能凭描述重新猜测。

复制页面的初始化提示词交给执行工具；生成后在**新项目**使用另一个接管按钮。不要在本仓库根目录或 current 内开发/初始化业务项目，也不要用 `--force` 覆盖已有目录。

最小命令示例（在本仓库根目录运行，目标为仓库外的全新目录）：

```sh
python current/starter.py init --target "../demo-lite" --name "演示项目" --description "本地简单记录工具" --profile generic --governance-mode lite
```

然后打开生成的 demo-lite，把以下话交给执行工具：

> 读取 START_HERE.md、PROJECT.toml 和当前上下文，按实际治理模式接管，先确认需求基线，不立即写业务代码。只加载本任务有关的正式事实与代码。

更多操作见 [快速开始](current/QUICK_START.md)。工具自身维护从 [START_HERE](START_HERE.md) 进入。

## 测试与限制

从仓库根目录运行：

```sh
python -B current/run_tests.py --report-dir "validation/local-run"
```

报告目录必须在 current 外；`--verbose` 可显示每个成功用例。默认保留原始日志并输出摘要。测试会建立临时 Git 项目，缺失 Python/Git/Node 会失败，不依赖作者的缓存目录或已有 Git 身份。Linux/Windows 工作流配置位于根 `.github/workflows`；本轮没有运行远端 CI，不附通过徽章。

本地通过不代表全部平台兼容。页面测试使用模拟 DOM/剪贴板，不能代替真实浏览器点击：打开页面，核对实际路径，分别复制两个提示词并粘贴到空白编辑器确认内容。遇权限拒绝可手动全选复制。

项目内历史报告仅代表当时环境与源码，本地保留的旧数字不是当前版本的自动保证。不宣传未经实际 usage 测量的 Token 节省比例。无授权联网、付款、发布或修改真实业务项目的默认权限。
